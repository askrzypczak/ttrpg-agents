# dm-prep evals

Prompt evals for `SKILL.md`. Run each sentence in a fresh `claude -p` session from the repo root with the project MCP server `ttrpg-agents` enabled and `TTRPG_AGENTS_DB` pointing at a throwaway file (a linked worktree uses the `dev` profile instead). "DM text" means the page file named in the sentence, from `fixtures/test-book/pages/`, pasted into the sentence as it is (the test book is invented, so pasting it is allowed). "Empty" means nothing stored and no encounter. "Harrier stored" means the Ashfeather Harrier is stored: row 5's `create_creature` call, run first. "Shaman stored" means a stored Goblin Shaman (`homebrew_goblin-shaman`, made as in row 1) and one in an encounter, added with `add_monsters`. "Goblin art" means a Goblin Warrior in an encounter, added with `add_monsters` while online, so the type has its TooManyTokens default (row 9 run first). "Own image" means an image file the tester draws for the run, outside the repo, at /tmp/wolf-art.png, with the animal's face in the upper left quarter (never book art; the repo holds no image fixture). "Wolf GM pick" means the Wolf type's art was chosen in the Owlbear extension panel (needs the Owlbear test scene). Rows 9 to 12 need internet. A multi-turn row runs each later sentence in the same session with `claude -p --continue`. Rows 7 and 8 name the stored creature on purpose: with a Goblin Shaman both stored and in the encounter, the bare "make the goblin shaman AC 14" is ambiguous and the skill asks (see Same names). A sentence passes when the calls match and every number in the answer comes from tool output or the DM text. A `table_status` call is fine in any row.
